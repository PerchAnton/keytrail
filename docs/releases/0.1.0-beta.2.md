# KeyTrail 0.1.0-beta.2 — preparation only

This is an **unpublished development candidate**, not a qualified release.
Package metadata, the reported runtime version and the default publication channel
are aligned on beta.2 / `beta`. Existing tags are unchanged.

The branch joins the published beta.1 history (`ae553d6`, qualified source
`f775b30`) with the grouped-locator changes from main (`fa2b125`) and the strict
report-validator fix. The original source and regression tests are retained.
The beta.1 package remains available for trials pinned to its exact version.

The [observation reader](../observation-gaps.md) also reduces repeated manual
sampling from four protocol requests to one when grouping is safe. Fresh query
membership and mutation guards retain ambiguity and context checks. Added
regressions and the actual-report CI gate preserve strict validation. This
addresses avoidable request overhead; it does not guarantee that a shared runner
will never exceed the unchanged 100 ms limit. The previous 130.2 and 107.3 ms
failures remain recorded, and the new code requires its own bounded CI results.

   consumers. The limit stays **100 ms**, with **zero retries**.
2. Select a source commit and separately authorize final qualification: fresh
   benchmark and guard evidence, 10 sequential rounds, the four-worker comparison
   and independent validation of all original reports against that source.
3. Update the evidence only from those successful runs. Run
   `node scripts/check-package.mjs --release` and retain the exact archive,
   SHA-256 checksum and clean-consumer results.
4. Confirm publication separately. Publish only the verified archive under `beta`;
   a green ordinary CI job does not authorize or qualify publication.
