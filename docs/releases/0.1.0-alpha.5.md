# KeyTrail 0.1.0-alpha.5 — draft first-release notes

**Prepared, not published.** KeyTrail checks declared keyboard journeys in
Playwright: custom ARIA dialogs, automatic/manual tab lists, and form-error recovery.
It reports the first mismatch and preserves observations that could not run.

- Typed contracts, ESM/CJS exports and schema-v1 JSON attachments.
- An optional CI guard rejects missing, incomplete and failed journey reports,
  including skipped tests and attempts recovered by retry.
- Runnable vanilla and React portal examples show corrected components and
  deliberate defects. The same archive is installed into two clean offline consumers.
- The React example uses StrictMode, unmount/remount, HTML/JUnit reports and a
  negative control that exits 1 with its incomplete attachment intact.
- Verification includes 153 browser tests, 30 unit tests and 48 guard subprocess
  cases. The accepted repeatability checkpoint is 45 full sequential rounds
  (6,885 executions), plus matching four-worker results. The original 100-round
  criterion was not completed.
- Synthetic benchmarks compare equivalent native Playwright actions and checks.
  All three recorded workloads meet the 20% median overhead target; the results
  are specific to the documented runner and fixtures.

This is an early alpha. Chromium, Node 24 and the exact pinned Playwright peer are
the tested scope. No native/nested dialogs, iframe, Shadow DOM, screen-reader
assessment or full accessibility certification is claimed. A short ordinary
Playwright test may be preferable when a reusable journey contract adds no value.

Use the local tarball instructions in README until publication is verified.
