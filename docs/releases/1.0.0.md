## Release gates

- [ ] Review API commitments and confirm runtime changes are metadata only.
- [ ] Pass types, unit/script/guard checks, Linux and three separate ARM allocations,
      including validation of real reports and both package consumers.
- [ ] Freeze candidate source/verification inputs and record its identity.
- [ ] After explicit authorization, run fresh benchmark and **10 final rounds**,
      then the separate four-worker comparison. Preserve 100 ms, retries/skips=0.
- [ ] Independently validate all raw reports, hashes and signatures. Retain the
      0.1.0 records as historical; never substitute or relabel them for this candidate.
- [ ] Record candidate acceptance policy, benchmark and CI guard evidence, then
      require `node scripts/check-release-readiness.mjs --json` to succeed.
- [ ] Run `node scripts/check-package.mjs --release`; retain the exact verified
      archive, consumer reports and checksum. Development packages are not release proof.
- [ ] Review/merge and require successful main CI. Obtain publication authorization,
      use a new v1.0.0 tag and upload the verified archive without rebuilding it.
- [ ] Download npm bytes, compare hash/integrity and clean installation; preserve
      beta and old releases before marking README and GitHub release as published.

The final series is deliberately not started by preparation or ordinary CI.
`docs/evidence/acceptance-policy.json` has no candidate series identity yet, so
the release-readiness check must fail until genuine final evidence is recorded.
The old candidate tag and published release tags stay unchanged.

## Announcement draft (only after publication)

KeyTrail 1.0 provides repeatable Playwright keyboard journeys for dialogs, tabs
and form errors, with a documented API and CI guard. Run the dialog example to see
the first focus mismatch and its HTML report. It checks the supplied contracts in
the supported environment; it does not certify accessibility or replace native
tests, assistive-technology checks or manual testing. No external adoption or
performance improvement is implied by the version number.
