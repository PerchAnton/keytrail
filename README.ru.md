# KeyTrail

Проверка клавиатурного сценария модального окна в существующих тестах Playwright.
Вы задаёте элементы и ожидаемый порядок фокуса; KeyTrail нажимает клавиши и показывает
конкретное расхождение, а также проверки, которые не удалось выполнить.

[English](README.md) · [API](docs/api.md) · [Ограничения](docs/limits.md) · [План](docs/roadmap.md)

**Сейчас:** первый рабочий прототип `0.1.0-alpha.1`, исходники и локальная сборка пакета.
Публикация в npm и GitHub Release ещё не выполнялась. Реализованы custom ARIA dialogs;
вкладки, ошибки форм и контроль полноты CI относятся к следующим этапам.

Основной пример: окно закрывается по Escape, но фокус остаётся в body. Результат:

```text
D07 FOCUS_MISMATCH expected=open-profile observed=body
```

После исправления компонента тот же контракт проходит. В репозитории есть исправная
и намеренно сломанная страницы. Это учебный дефект, а не обнаруженная ошибка чужого проекта.

## Запуск

Нужны Node.js 24 и pnpm 11.25.0. Проверяемая версия Playwright — 1.64.1.

```sh
git clone https://github.com/PerchAnton/keytrail.git
cd keytrail
pnpm install --frozen-lockfile --ignore-scripts
pnpm exec playwright install chromium
pnpm build
pnpm test:package
```

На Linux при необходимости: `pnpm exec playwright install --with-deps chromium`.
Последняя команда собирает архив, устанавливает его в чистый временный проект,
проверяет ESM/CJS и TypeScript и выполняет оба примера в Chromium.
Архив сохраняется в `artifacts/keytrail-0.1.0-alpha.1.tgz`.

[Пример с HTML и тестом](examples/vanilla) можно перенести в свой Playwright-проект.
Один тест вызывает один сценарий. В рабочих тестах не подавляйте `JourneyAssertionError`.
Собственный JSON-отчёт прикладывается к стандартному отчёту Playwright.

## Область проверки

Проверяются вход через Tab, семантика окна, начальный фокус, прямой и обратный обход,
закрытие по Escape и возврат фокуса. Поддержаны один элемент, начальный фокус на
статическом заголовке, отложенный рендер и альтернативная точка возврата.

Статусы `pass`, `fail`, `blocked`, `not_run` различаются. Пропущенные наблюдения не
исчезают из результата. Полнота и общий исход учитываются отдельно.

Это инструмент проверки заданного поведения. Он не выдаёт сертификат доступности,
не заменяет экранный диктор, ручной аудит или небольшие обычные Playwright-тесты.
Производительность относительно ручных проверок пока не измерена; полная приёмка
0.1.0 ещё впереди. [Фактически выполненные проверки](docs/verification.md).
